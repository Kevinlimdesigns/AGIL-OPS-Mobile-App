## 📐 AOH adherence
**Good:** type/spacing/radius/size all tokenized; new tokens are on-scale (`Radius/radius-round`, `Spacing/spacing-3xs`, `color-bg-interactive-muted`). Status states pair colour with **icon + text label** (e.g. "LIVE", "RECEIVING") — not colour-only ✓ (M3/WCAG).

**Drift to fix:**
- **`comms/*` local tokens** (`bar-surface`, `bar-text-primary/secondary`, `avatar-surface`, `mic-surface`) — now used across the whole new comms suite but still defined **outside AOH**. Governance decision overdue: promote into AOH or formally sanction as app-level.
- **Orange "Live-weak"** state (`Talk bar — States`) has **no AOH orange token** (palette is yellow/red/green/blue) → almost certainly hardcoded. Add a token or remap.
- **`Mobile/Button` pressed** uses a raw 14% black overlay — no AOH **state-layer** token exists. Add one to fully tokenize pressed states.

## 📱 Mobile spec (M3) compliance
- **Touch targets:** today's fixes hold (Filter Chip / Checklist / Detail-Field / Status Banner / Mobile-Button all **48 dp**). New comps pass from metadata: Talk bar States 72 · PTT Log Row 82 · PTT Controls 120 · Contact chip 84 · banners 76 ✓.
- **Verify (not decidable from metadata):** `469:262` **Context menu** row heights (menu is 190 tall — ensure each row ≥48 dp); `524:15271` **PTV/Control Button** icon target (≥48 dp).
- **States:** `Mobile/Button` has Default/Pressed/Disabled/Loading ✓. Other button **types** (secondary/outline/destructive) not built yet; PTV control button has Default/Destructive only.
